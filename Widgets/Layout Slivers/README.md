# Layout: Slivers

Slivers are scrollable layout regions that cooperate inside a viewport. Unlike
box widgets, which receive `BoxConstraints` and return a two-dimensional size,
slivers receive `SliverConstraints` and report how much scroll extent they
occupy and how much is currently visible. This protocol lets a single scroll
view combine collapsing headers, lazy lists, grids, padding, and ordinary box
content without eagerly laying out the whole page.

Use `CustomScrollView` when a scrolling surface needs more than one kind of
region. Choose a lazy delegate for large or unbounded collections, an extent-
based list when rows share a predictable main-axis size, and
`SliverToBoxAdapter` for occasional box content. Headers belong in
`SliverAppBar` or `SliverPersistentHeader`; remaining-space behavior belongs in
`SliverFillRemaining` or `SliverFillViewport` rather than in nested scroll
views.

Sliver performance depends on creating only the children near the viewport and
on preserving their identity when data changes. Supply stable keys, accurate
child counts, and a `findChildIndexCallback` when keyed children can reorder.
Avoid wrapping every box in its own adapter, be deliberate about keep-alives
and repaint boundaries, and test empty, short, long, reordered, and overscrolled
content on viewports of different sizes.
