# Layout: Single Child

Single-child layout widgets modify how one child is constrained, sized,
positioned, painted, or exposed within the safe parts of the screen. Flutter
layout flows downward as constraints, upward as sizes, and then downward again
as positions. Most surprises in this category come from choosing a widget that
changes a different stage of that flow than intended.

Choose a widget by the smallest layout responsibility it needs to own. Use
`Padding` for insets, `Align` or `Center` for position, and `SizedBox` or
`ConstrainedBox` for explicit constraints. Reach for `FittedBox` when content
must be scaled at paint time, `Transform` when only its painted geometry should
move, and `CustomSingleChildLayout` only when ordinary constraint and alignment
widgets cannot express the relationship. Prefer `ColoredBox` or `DecoratedBox`
over `Container` when only painting is required.

Constraint-sensitive widgets need particular care. Intrinsic measurement can
add an expensive speculative layout pass, overflow widgets can paint outside
their allocated space without giving siblings more room, and an unconstrained
axis can leave a child with no finite size to target. Test layouts with narrow,
wide, short, text-scaled, and system-inset-heavy viewports rather than relying
on one device size.
