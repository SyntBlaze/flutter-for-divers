## Best Practices

- Use `Align` when positioning is the main responsibility and constraints provide meaningful spare space
- Treat an aspect ratio as a preference that must remain compatible with parent constraints
- Coordinate explicit baselines only for children that report the intended text baseline
- Use `Center` for straightforward centering and `Align` for any broader positioning need
- Express reusable size bounds with `ConstrainedBox` instead of scattered dimension checks
- Replace `Container` with focused widgets when only one layout or painting behavior is needed
- Keep custom layout delegates small, deterministic, and precise about when relayout is required
- Give `FittedBox` bounded space and choose a fit that preserves the intended cropping behavior
- Use fractional sizing only where the parent supplies a finite reference dimension
- Avoid `IntrinsicHeight` in long lists or deeply nested layouts
- Prefer explicit constraints over `IntrinsicWidth` when the desired width is already known
- Use `LimitedBox` specifically as a fallback for unbounded constraints
- Stop unnecessary animations and manage focus deliberately in offstage subtrees
- Make overflow intentional and test its clipping, hit testing, and accessibility behavior
- Use `EdgeInsetsDirectional` for spacing that should mirror with text direction
- Use `SizedBox` for explicit dimensions and simple gaps, while respecting incoming bounds
- Use `SizedOverflowBox` only when the outer allocation and child constraints must intentionally differ
- Prefer layout widgets when neighboring content should respond to a visual movement
- Release only the necessary axis with `UnconstrainedBox` and ensure the child remains finitely sized
- Place `SafeArea` at meaningful screen boundaries and configure only the sides that need protection
- Use `ColoredBox` for a solid background without unrelated container behavior
- Pair `DecoratedBox` with explicit padding when decoration content needs breathing room
