# Animation and Motion

Flutter's animation widgets range from implicit widgets that animate a changed
property automatically to transition widgets driven by an explicit
`Animation<double>`. Implicit widgets are usually the clearest choice for a
single destination value, while explicit transitions provide coordinated
timelines, reversible motion, and shared controllers. List, hero, and modal
barrier APIs address specialized animation lifecycles.

Choose the smallest animation model that expresses the interaction. Start with
an `AnimatedContainer`, `AnimatedAlign`, or another implicit widget when the
parent only needs to supply a new target value. Use `AnimatedBuilder`, an
`AnimatedWidget` subclass, or a focused transition when several properties must
follow the same animation. Pass invariant subtrees through a `child` parameter
where available, and compose transitions around that child instead of
rebuilding it on every tick.

Motion should explain a state change rather than delay it. Keep duration,
curve, layout cost, clipping, hit testing, and accessibility preferences in
view. Layout animations such as size and position can be more expensive than
paint-only opacity, scale, or rotation effects, and invisible content may still
participate in layout, semantics, or pointer interaction unless handled
explicitly.
