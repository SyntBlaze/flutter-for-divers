# Material: App Structure and Navigation

Material app structure separates application-wide configuration, per-screen
visual scaffolding, navigation destinations, and content that changes within a
destination. `MaterialApp` establishes the Material environment and usually
owns top-level routing. Each route commonly contains a `Scaffold`, which
coordinates standard surfaces such as an app bar, body, drawer, bottom bar,
floating action button, and snack bars.

Choose navigation from the number and hierarchy of destinations, the available
width, and platform expectations. `NavigationBar` is the Material 3 choice for
a small set of primary destinations on compact layouts, while `NavigationRail`
fits wider layouts and `NavigationDrawer` exposes more destinations or
supporting routes. Tabs switch between closely related peer views inside the
same context; pages provide swipeable, controller-driven content. Use
`Navigator` or a routing package for route history rather than treating a tab
or selected destination index as a complete navigation stack.

App bars and navigation controls should reflect the same source of truth as the
visible content. Keep selection state restorable when appropriate, preserve
independent nested navigation stacks only when the product requires them, and
adapt between compact and expanded navigation without losing the current
destination. Account for system insets, keyboard navigation, large text, and
display cutouts, and verify that labels and selected states remain clear to
assistive technologies.
