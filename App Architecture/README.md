# App Architecture

A practical index of Flutter project structures, architectural patterns,
boundaries, dependency rules, configuration, dependency injection, error
handling, and code organization. Browse a category below, then open a topic for
focused notes and examples.

## At a glance

- [Project Structure](<Project Structure/README.md>) — Arranging entry points, features, layers, and reusable code so ownership and dependency direction stay visible
- [Architecture Patterns](<Architecture Patterns/README.md>) — Separating presentation, business rules, data access, and external systems with appropriate architectural boundaries
- [Layer Responsibilities](<Layer Responsibilities/README.md>) — Defining where each kind of code belongs and protecting application policy from external details
- [Dependency Rules](<Dependency Rules/README.md>) — Controlling which application parts may know about one another and directing dependencies toward stable policy
- [App Configuration](<App Configuration/README.md>) — Selecting and validating environment, build, installation, and runtime settings without scattering configuration logic
- [Dependency Injection](<Dependency Injection/README.md>) — Building dependency graphs, selecting implementations and lifetimes, and supplying collaborators at a composition root
- [Error Boundaries](<Error Boundaries/README.md>) — Capturing, translating, reporting, and presenting operational failures and unexpected errors at appropriate boundaries
- [Code Organization](<Code Organization/README.md>) — Giving source files clear purposes, names, and homes while separating generated and test-only code
